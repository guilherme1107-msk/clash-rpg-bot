## Tarefa 1 — Mover o projeto para fora do Codex

**Decisão:** `Move-Item` para `C:\Users\Usuário\Documents\clash-rpg-bot`.

**Por que assim:**

- O destino é o mesmo disco (`C:`). No Windows um move entre pastas do mesmo
  volume é um **rename de metadados**, não uma cópia — o projeto tem ~1,5 GB
  (com `.venv` e `node_modules`), então copiar levaria minutos e dobraria o
  uso de disco. Medido: **0,05 s**.
- `Documents\clash-rpg-bot` foi escolhido entre as opções oferecidas por ser
  caminho curto, **sem espaços e sem acento**. Isso não é frescura: caminho com
  `Usuário`/espaço quebra `.bat`, `csc.exe`, `spawn` sem `shell:true` e
  configuração de `.env`. Já existe um `Documents\clash-rpg-bot.zip`, sinal de
  que é a casa natural do projeto.
- Rodei o comando com o *working directory* fora do projeto, para o shell não
  segurar a pasta que estava sendo movida.
- Logo depois, movi a própria sessão de trabalho com `session_move`, senão todos
  os próximos passos apontariam para um caminho que não existe mais.

**Validação pós-move:**

- `.git\index` e `.venv\Scripts\python.exe` presentes.
- `python -V` → 3.12.14; `import discord, dotenv` → ok.
- **117 testes → OK** em 1,86 s.
- Todos os `.bat` do projeto usam `cd /d "%~dp0"` (relativos) — nenhum precisou
  de ajuste. Confirmei isso *antes* de mover, justamente para não ter que
  caçar caminho absoluto quebrado depois.

## Tarefa 2 — Separar a UI da Rosemary

**Decisão:** mover `ui/rosemary-panel` para
`C:\Users\Usuário\Documents\Rosemary game\rosemary-panel`, e os dois backups
(`.rar` + `.zip`, 469 MB) para `Documents\Rosemary game\_backup-archives\`.

**Por que assim:**

1. **Primeiro provei que era seguro.** Fiz varredura por texto em todo o código
   (`.py`, `.bat`, `.cmd`, `.ps1`, `.html`, `.js`, `.jsx`, `.json`, `.md`)
   procurando `ui/rosemary-panel` e `ui\rosemary-panel`. **Zero referências de
   caminho.** Os únicos "matches" eram o `name` do próprio `package.json` e
   entradas de lockfile. Ou seja: o bot não sabe que essa pasta existe.
2. **Separar ≠ apagar.** O que é Rosemary *dentro* do bot (`rosemary_panel.py`,
   `rosemary_content.json`, as tabelas `rosemary_*`, os comandos em `bot.py` e
   `control_center.py`) **ficou onde estava**. Isso é código de combate/estado
   ligado ao `database.py` — mexer seria mexer no motor, e não era o pedido.
   Quem sai é só a **UI Electron**, que é um app próprio com `package.json`,
   `node_modules` e `electron/` dela.
3. **`Rosemary game\` em vez de `Documents\`** porque você já tem lá
   `rosemary-desktop` e `rosemary-game`. Juntar os três projetos dela num lugar
   só é mais organizado do que espalhar na raiz de `Documents`.
4. **Os `.rar`/`.zip` foram para `_backup-archives\`** e não para dentro da
   pasta do painel: eram 469 MB de cópia do próprio painel — guardá-los dentro
   dele seria um backup que se auto-referencia, e ainda poluiria a pasta do
   projeto. Não apaguei porque você não pediu para apagar.

**O único acoplamento real — e como resolvi:**

`ui/rosemary-panel/electron/main.cjs` fazia:

```js
const botDir = path.resolve(projectDir, '..', '..')   // sobe 2 níveis = raiz do repo
```

Ou seja, o Electron **subia o `control_center.py` do bot** assumindo que estava
dentro do repositório. Mover a pasta quebraria isso em silêncio (a janela
abriria com erro genérico). Troquei por uma cadeia de resolução:

1. `CLASH_BOT_DIR`, se definida;
2. senão o caminho relativo legado, **mas só se** `control_center.py` existir lá;
3. senão `botDir = null` → o painel **não tenta subir o bot**, só espera a
   Central em `127.0.0.1:8765`. Se ela não responder, a tela de erro agora
   manda configurar `CLASH_BOT_DIR` em vez de sugerir reinstalar o Python.

**Por que `CLASH_BOT_DIR` e não caminho absoluto fixo no código:** caminho
absoluto hardcoded quebra no próximo move e não sobe para o GitHub. Variável de
ambiente + fallback de convenção é o padrão; o `.cmd` de atalho já pré-configura
a variável quando detecta a pasta, então para você nada muda no uso diário.

`node --check` no `main.cjs` → OK. `node_modules` do painel intacto.

**Decisão menor:** o `.cmd` usa `%USERPROFILE%\Documents\clash-rpg-bot` em vez
de `C:\Users\Usuário\...`. Evita `á` dentro de arquivo `.bat` (problema clássico
de codepage) e continua funcionando se o diretório de usuário mudar.

**Por que assim:**

- **Não escrevi o texto de cabeça.** Licença é documento legal; qualquer vírgula
  errada a invalida. Baixei a fonte oficial e validei antes de aceitar:
  674 linhas, 35.149 bytes, `Version 3, 29 June 2007`, seções **0 a 17
  completas** (Definitions → Interpretation of Sections 15 and 16),
  `END OF TERMS AND CONDITIONS` e o apêndice "How to Apply These Terms".
- **GPL-3.0 foi a sua escolha**, e o efeito dela é *copyleft*: qualquer um pode
  usar e até comercializar, mas se distribuir uma versão modificada é obrigado
  a publicar o código dela sob a mesma licença. Se quiser mudar depois (ex. para
  MIT ou "todos os direitos reservados"), é trocar o arquivo `LICENSE` e o
  parágrafo do README — sem efeito retroativo sobre cópias já distribuídas.
- **Escrevi em português no README o que a licença cobre e o que não cobre.**
  Você disse que não entende muito do assunto, e o ponto que mais gera confusão
  é este: **a GPL vale só para o código escrito aqui.** Ela não torna
  redistribuível GIF, sprite, emoji ou imagem de Project Moon/Limbus Company.
  Um `LICENSE` não conserta falta de permissão de terceiro — deixei isso explícito.
- **O README foi atualizado** porque dizia "Nenhuma licença foi escolhida
  ainda" — deixar lá seria mentira documental.

## Tarefa 4 — Completar o `.gitignore`

**Decisão:** reescrever o arquivo (20 → 47 regras) organizado por seções com
comentário, mantendo todas as regras antigas e acrescentando as que faltavam.

**Vazamentos reais confirmados no disco antes da mudança:**

| Arquivo | Tamanho | Estava coberto? |
|---|---|---|
| `clash_rpg.sqlite3-wal` | **4,12 MB** | ❌ `*.sqlite3` não casa com `.sqlite3-wal` |
| `clash_rpg.sqlite3-shm` | 32 KB | ❌ idem |
| `ClashBot.exe` | **1,89 MB** | ❌ só existia a regra `tools/cloudflared.exe` |
| `ui/rosemary-panel/node_modules/` | ~500 MB | ❌ só `ui/discord-activity/node_modules/` estava listado |
| `ui/rosemary-panel/dist/` | ~10 MB | ❌ só `ui/discord-activity/dist/` estava listado |
| `rosemary-panel.rar` + `.zip` | **469 MB** | ❌ nenhuma regra |

**Por que assim:**

- **Curingas genéricos em vez de caminhos pontuais.** Trocar
  `ui/discord-activity/node_modules/` por `node_modules/` e
  `ui/discord-activity/dist/` por `dist/` resolve todos os apps de uma vez,
  hoje e no próximo que você criar em `ui/`. Caminho ancorado só resolve o caso
  que já deu problema.
- **`*.sqlite3-*` é a correção importante.** O modo WAL do SQLite gera três
  arquivos ao lado do banco (`.sqlite3`, `.sqlite3-wal`, `.sqlite3-shm`). O
  curinga `*.sqlite3` cobre só o primeiro. Foi exatamente por isso que 4 MB de
  histórico de transação quase entraram no Git.
- **Ordem importa em `.gitignore`.** `.env.*` ignora o `.env.example`, então a
  exceção `!.env.example` precisa vir **depois** — deixei o comentário no próprio
  arquivo para ninguém "limpar" essa linha achando que está duplicada.
- **Comentários em cada seção** explicando o porquê, porque a reclamação clássica
  é alguém "simplificar" o arquivo depois e reintroduzir o vazamento.
- **Não ignorei `tools/` inteiro.** O original só barava `tools/cloudflared.exe`,
  ou seja a pasta é pensada para utilitários versionáveis. `*.exe` já cobre o
  binário sem bloquear os scripts.

**Validação:** como `git` não está instalado, implementei um matcher de
regras `.gitignore` (ordem, `!` negação, `dir/`, ancoragem por `/`, `*` vs `**`)
e rodei contra a árvore real:

```

VAZAMENTOS DETECTADOS: 0
.env            -> IGNORA      .env.example  -> COMMITA
clash_rpg.sqlite3-wal -> IGNORA   src/domain/combat/engine.py -> COMMITA
```
